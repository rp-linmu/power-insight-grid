# 广东交易中心本地原始 Excel 获取工具

这个项目通过已完成 UKey 登录的 Chrome 页面进行模拟点击导出，只访问广东交易中心页面，不访问辅助系统或数据中心，也不直接拼接导出接口。

## 当前已接入的数据项

已接入并可通过可视化页面执行：

- 市场出清：首页“现货分日出清量价”模块导出
- 基本面数据：信息披露查询“预测”页全部导出
- 日前节点电价：日前节点电价查询页面导出
- 实时节点电价：实时节点电价查询页面导出
- 现货分时分类型出清电量：首页模块分别导出“日前”和“实时”

当前登录页面菜单里暂未定位到可点击入口，界面中保留为“待接入”：

- 日清算概览
- 月结算概览
- 市场主体
- 交易市场行情

## 使用方式

复制配置：

```powershell
Copy-Item .\config.example.json .\config.local.json
```

启动可视化控制台：

```powershell
node .\src\index.js web --config .\config.local.json --port 8787
```

打开：

```text
http://127.0.0.1:8787
```

页面可以选择日期范围和数据项，然后按顺序驱动已登录 Chrome 模拟点击下载。

## Chrome 登录要求

需要先用 UKey 登录广东交易中心，并让 Chrome 暴露 DevTools 调试端口。配置项：

```json
{
  "auth": {
    "chromeDebugUrl": "http://127.0.0.1:9222"
  }
}
```

## 输出目录

模拟点击下载的原始 Excel 会按数据项名称保存：

```text
data/browser-downloads/<数据项名称>/<选择日期>/<交易中心原始文件名>.xlsx
```

多页签数据会再分子目录，避免相同原始文件名互相覆盖：

```text
data/browser-downloads/现货分时分类型出清电量/2026-05-26/日前/<原始文件名>.xlsx
data/browser-downloads/现货分时分类型出清电量/2026-05-26/实时/<原始文件名>.xlsx
```

交易中心可能按平台可披露运行日返回上一日文件名，例如选择 `2026-05-26` 时原始文件名仍可能包含 `2026-05-25`。工具会保留平台原始文件名，并按你选择的日期归档。

## 校验

“检查缺失数据”不仅检查文件是否存在，还会读取 Excel 工作簿内容。以下情况均视为缺失并进入补采清单：

- 文件大小为 0、文件损坏或没有工作表；
- 工作簿只有表头，没有任何有效数据行；
- 数据区全部为空；
- 文件名中的业务日期与目录日期不一致。

补充获取时，无效旧文件会被删除并重新下载。新下载文件必须同时通过日期校验和内容校验；如果交易中心仍未发布数据，空文件会被删除，任务标记为失败，并在下次检查时继续进入补采清单。

```powershell
npm.cmd run check
```

## 日期校验与单日测试

工具会打开页面日历，根据日历标题导航到目标年月，再点击具体日期进行确认。
输入框未更新为目标日期时，任务会立即失败，不会执行下载。日期确认后工具会尝试触发页面查询，并校验下载文件名中的业务日期。
如果下载文件日期与请求日期不一致，工具会立即删除错误文件，并将该数据项标记为失败。

修改代码后需要重启 Web 控制台：

```powershell
cd ECsystem/gd-market-crawler
npm.cmd run check
node .\src\index.js web --config .\config.local.json --port 8787
```

建议先在控制台中选择一个历史日期和一个数据项进行测试。下载完成后，再点击“检查缺失数据”确认文件日期和目录日期一致。

## 按缺失清单补充获取

在控制台中完成“检查缺失数据”后，检查结果会生成精确的“日期 + 数据项”补采清单。
保持“补充获取”开启并点击运行时，工具只执行该清单，不再遍历整个日期范围中的已完整数据。

如果检查后修改了日期范围或数据项选择，需要重新点击“检查缺失数据”，避免使用过期清单。
