# 电力交易信息网站建设方案

## 1. 项目定位

网站目标不是做一个简单的数据展示页，而是建设一个面向电力交易场景的“信息中台 + 分析门户”。

相比原始设想，建议在原有三大模块基础上做以下增强：

- 在信息披露模块中增加“统一数据标准层”，避免后续 Excel 来源不统一导致维护困难
- 在政策文件模块中增加“标签体系 + 自动摘要”，让用户按市场、主题、发布时间快速筛选
- 在预测模块中增加“结果解释层”，不仅展示预测值，还展示方向、置信度和驱动因子
- 预留“分析看板首页”，把最关键的数据、政策变化、预测结果集中呈现

## 2. 推荐的网站结构

### 2.1 首页看板

建议首页不是纯导航页，而是决策看板，包含：

- 今日关键指标卡片
  - 日前价格
  - 实时价格
  - 统调负荷峰谷
  - 新能源出力水平
- 最新政策速览
- 预测结果摘要
- 重点异常提示

这样用户进入网站后可以先快速了解“今天发生了什么”。

### 2.2 信息披露模块

建议拆成 4 个子能力：

- 数据总览
  - 日前与实时切换
  - 日期、区域、指标筛选
- 时序曲线展示
  - 24 点和 96 点自适应展示
  - 支持多指标对比
  - 支持峰平谷区间高亮
- 表格明细
  - 支持分页、导出、同比环比
- Excel 导入中心
  - 模板校验
  - 导入日志
  - 错误提示

建议数据模型统一为：

- `data_date`: 业务日期
- `market_type`: 日前 / 实时
- `region`: 区域
- `indicator_code`: 指标编码
- `indicator_name`: 指标名称
- `time_granularity`: 24 / 96
- `point_index`: 点位序号
- `point_time`: 点位时间
- `value`: 数值
- `unit`: 单位
- `source_file`: 来源文件
- `import_batch_id`: 导入批次

对于结构化文本类数据，建议也通过 Excel 导入，但入库前先做字段标准化。

### 2.3 政策文件模块

建议不仅存文件，还要形成“可检索、可理解、可摘要”的知识库：

- 文件列表
  - 标题、发布时间、发布机构、适用区域、主题标签
- 文件详情
  - 原文预览
  - 核心摘要
  - 重点条款提炼
  - 对市场影响的简明说明
- 检索能力
  - 按关键词、机构、区域、主题、时间筛选
- AI 辅助能力
  - 自动摘要
  - 关键条款提取
  - 面向用户的“一句话说明”

建议标签体系至少包括：

- 市场类型
- 交易品种
- 价格机制
- 偏差考核
- 新能源
- 需求响应
- 辅助服务
- 结算规则

### 2.4 预测模块

建议从“只展示预测结果”升级为“预测展示 + 解释 + 评估”：

- 电价预测
  - 日前价格短周期预测
  - 实时价格短周期预测
- 价差方向
  - 峰谷价差方向
  - 日前-实时偏差方向
- 结果解释
  - 主要驱动因素
  - 历史相似日参考
  - 模型置信区间
- 模型评估
  - MAE / RMSE / MAPE
  - 历史回测图

如果你当前还没有成熟模型，一期可先采用“规则模型 + 可视化框架”，先把展示和数据链路打通，后续再替换成机器学习或深度学习模型。

## 3. 推荐技术方案

## 3.1 前端

建议：

- `Next.js`：适合做数据网站与内容网站结合的项目
- `TypeScript`：增强可维护性
- `Ant Design` 或 `MUI`：提升后台型页面开发效率
- `ECharts`：做电力时序曲线、对比图、热力图很合适

前端页面建议包括：

- 首页看板
- 信息披露列表页
- 信息披露详情页
- Excel 导入页
- 政策文件列表页
- 政策文件详情页
- 预测总览页
- 预测详情页
- 后台管理页

## 3.2 后端

建议：

- `Python FastAPI`
- `PostgreSQL`
- `SQLAlchemy`
- `Pandas`

原因：

- Excel 导入、数据清洗、时序处理对 Python 很友好
- FastAPI 适合快速建设接口服务
- PostgreSQL 适合结构化数据、检索与扩展

## 3.3 AI 与文本处理

政策文件摘要与提炼建议预留 AI 服务层，后续可接：

- OpenAI API
- Azure OpenAI
- 本地大模型服务

AI 能力适合做：

- 文件摘要
- 条款提炼
- 风险点总结
- 面向交易员的简明解读

## 4. 推荐分期建设

### 一期：先跑通最小可用产品

- 用户可查看信息披露数据
- 管理员可通过 Excel 导入数据
- 用户可查看政策文件列表和详情
- 用户可查看预测结果曲线和方向

### 二期：增强分析能力

- AI 摘要与政策解读
- 更强的检索与筛选
- 回测与模型评估
- 指标对比与专题分析

### 三期：形成业务平台

- 权限管理
- 数据订阅与预警
- 多市场横向对比
- 决策辅助问答

## 5. 关键风险与建议

### 5.1 数据标准不统一

这是最大风险。建议一期优先定义 Excel 模板和字段标准，不要先收很多格式混乱的数据再处理。

### 5.2 预测模型过早复杂化

建议先搭展示框架和数据接口，再逐步替换模型，否则项目容易被模型训练拖慢。

### 5.3 政策文件质量参差不齐

建议先定义政策分类标准与摘要模板，不然不同文件的提炼结果会缺乏一致性。

## 6. 我建议的项目起步路径

最稳妥的路径是：

1. 先明确业务范围与数据标准
2. 先做网站一期静态结构与数据库设计
3. 再打通 Excel 导入
4. 再接政策文件管理
5. 最后接预测结果展示与 AI 总结

这条路径风险最低，也最容易尽快看到成果。
